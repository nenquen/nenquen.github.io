Learning Gentoo

This is not a "copy the command, hit enter, and figure it out if it breaks" guide. I explain each step in plain language, so that if something goes wrong, you understand where you are and what you're doing.

Learn it

Learn it

Gentoo won't hand you a ready-made desktop and say "take it". You choose the parts of the system yourself. For now it's enough to know these concepts:

Stage 3
The ready-made base system we start from. We don't compile everything from scratch.
Portage
Gentoo's package manager. Its main tool: emerge.
USE flags
Let you make choices like "Should I include KDE support? Bluetooth?".
Init system
Starts and stops services. In this guide the steps change based on your choice of OpenRC (default) or systemd.
Desktop / Purpose
You can install a desktop environment (KDE, GNOME, XFCE, LXQt) or a purpose-built server. The profile and installed packages change accordingly.
libc
The standard C library. The default is glibc; musl is lighter but has no desktop profiles. If you don't need a desktop (server/headless), musl is a good choice.
The most important advice: Don't memorize commands. Keep asking "Where am I right now, what am I installing?". Disk, chroot, Portage, kernel and bootloader are very different jobs. If you mix them up, Gentoo will greet you with creative error messages.
musl warning: musl ships with "experimental" profiles in Gentoo and has no desktop profile — this doesn't mean it can't be installed. Environments like KDE/GNOME can run on musl, but they don't rely on an official profile; you'll set up dependencies and USE flags manually. Also, some closed-source packages like Chromium/Chrome won't build with musl. If you're planning a desktop, my recommendation is glibc.
Boot the live USB

Boot the live USB

To start installing you need a working environment. Two options:

Minimal ISO
A plain, terminal-focused install environment.
Download current Minimal ISO
LiveGUI
A live environment with KDE desktop and graphical tools. More comfortable for Wi-Fi and browsing.
Download current LiveGUI
You'll need this later: The Stage 3 archive that is the foundation of the system we're going to install, which we'll download based on your choices. glibc + desktop + OpenRC: Desktop OpenRC Stage 3 glibc + desktop + systemd: Desktop systemd Stage 3 glibc + server + OpenRC: Base OpenRC Stage 3 glibc + server + systemd: Base systemd Stage 3 musl + OpenRC: musl OpenRC Stage 3 musl + systemd: musl systemd Stage 3
All AMD64 files are here.

After opening the live environment, make sure you're in UEFI mode:

UEFI check
ls /sys/firmware/efi

If the command lists something, you're good. If it's empty, reboot and select the UEFI entry from the boot menu.

For an MBR + BIOS install, make sure you open the live environment in legacy/BIOS mode (not UEFI mode).

Partition the disk

Partition the disk

The only tricky thing here: figuring out which disk you're working with. In Linux, disk names vary from system to system, so I don't hard-code a disk name in this guide. Start by listing them:

See the disks
lsblk -o NAME,SIZE,MODEL,TYPE,FSTYPE,MOUNTPOINTS

In the output, find the target disk by its model and capacity, then open the partitioning tool with that disk's name:

Partition · replace the placeholder with the real disk name
fdisk <TARGET_DISK>

Since you chose GPT + UEFI, I recommend a simple scheme:

  • EFI → 1 GiB → with t set to "EFI System" (1)
  • Swap → optional → "Linux swap" (19)
  • Root → the remaining space → "Linux filesystem" (20)

After creating the partitions, list again to learn the real partition names:

See the partitions again
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
No guessing. Replace these three placeholders (<EFI_PART>, <SWAP_PART>, <ROOT_PART>) with the real names you got from lsblk:
Create filesystems and mount
mkfs.fat -F 32 <EFI_PART>
mkswap <SWAP_PART>
mkfs.ext4 <ROOT_PART>
swapon <SWAP_PART>
mkdir -p /mnt/gentoo
mount <ROOT_PART> /mnt/gentoo
mkdir -p /mnt/gentoo/efi
mount <EFI_PART> /mnt/gentoo/efi

Since you chose MBR + BIOS, there is no EFI partition; the bootloader writes directly to the boot area before the first partition. The first partition must start at least 1 MiB in (from sector 2048). I recommend a simple scheme:

  • Root + /boot → all space → "Linux" (83)
  • Swap → optional → "Linux swap" (82)

Note: In the MBR scheme no separate EFI partition is needed. If you don't want swap, skip its placeholder.

See the partitions again
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
No guessing. Replace these placeholders (<SWAP_PART>, <ROOT_PART>) with real names. On MBR, if /boot is not separate it mounts into root:
Create filesystems and mount
mkswap <SWAP_PART>
mkfs.ext4 <ROOT_PART>
swapon <SWAP_PART>
mkdir -p /mnt/gentoo
mount <ROOT_PART> /mnt/gentoo
What did we do? With GPT+UEFI, the EFI partition is where the computer can boot from, the root partition holds Gentoo's files, and swap is extra space for RAM. With MBR+BIOS, the bootloader is written to the MBR and there is no EFI partition.
Get online

Get online

Since the installation downloads files from the internet, network is required. First check whether you have a connection:

Is there a connection?
ping -c 3 gentoo.org

If you're connecting over Wi-Fi

Find the wireless interface
ip link
iw dev

The interface name usually starts with wlp.... Don't get hung up on the name; the point is to find your card with iw dev.

Why does Wi-Fi sometimes not work? You need three pieces together: a kernel driver, the device firmware, and a connection manager. If one is missing, the connection won't start.

The easiest way: NetworkManager + nmtui

First connect in the live environment; we need to download the Stage 3 and packages before installing them. If you're using LiveGUI you can connect via the network icon, or open nmtui from a terminal. If NetworkManager isn't running, start it:

Check / start NetworkManager
rc-service NetworkManager status
rc-service NetworkManager start
Connect to Wi-Fi
nmtui

In nmtui, pick Activate a connection → select the Wi-Fi network → enter the password. Then test the connection.

Test the connection
ping -c 3 gentoo.org

Wi-Fi on the installed Gentoo

After we move into the chroot, we install NetworkManager. Do this only if the internet works from the live environment; otherwise Portage can't download packages. If you want to use iwd as the Wi-Fi helper, turn on the iwd USE flag first:

mkdir -p /etc/portage/package.use
echo 'net-misc/networkmanager iwd' > /etc/portage/package.use/networkmanager
NetworkManager + iwd
emerge --ask net-misc/networkmanager net-wireless/iwd
Run at boot · OpenRC
rc-update add NetworkManager default
rc-service NetworkManager start
Run at boot · systemd
systemctl enable --now NetworkManager

Then connect to the network with nmtui again and check:

Verify the connection
nmcli device status
ping -c 3 gentoo.org
Important: Run only one network manager at a time. When using NetworkManager, don't also enable dhcpcd/netifrc to manage the same interface; the results get confusing. Pick a single manager.

Don't want NetworkManager?

Alternatively you can use iwd or wpa_supplicant. Both are daemons needed for authentication; iw alone can't connect to Wi-Fi.

iwd
A new and simple wireless daemon. NetworkManager can also use it as a backend.
wpa_supplicant
Older but the most common option. You'll often see it in older guides.
My recommendation: If you're setting up a desktop, start with NetworkManager + nmtui. You can add iwd as a backend whenever you want.
Grab Stage 3

Grab Stage 3

Stage 3 is the ready-made base userspace of the system. Choose the right archive based on your choices:

  • Desktop → archive with the desktop suffix (same for KDE/GNOME/XFCE/LXQt)
  • Server → plain stage3-amd64-... archive
  • musl → archive with musl in its name (musl has no desktop variant)
  • OpenRC/systemd → archive with openrc / systemd in its name
cd /mnt/gentoo

I don't pin down the exact filename here because it changes as versions change. Get the real name from the current directory and use it.

tar xpvf stage3-amd64-desktop-openrc-*.tar.xz --xattrs-include='*.*' --numeric-owner
tar xpvf stage3-amd64-desktop-systemd-*.tar.xz --xattrs-include='*.*' --numeric-owner
tar xpvf stage3-amd64-openrc-*.tar.xz --xattrs-include='*.*' --numeric-owner
tar xpvf stage3-amd64-systemd-*.tar.xz --xattrs-include='*.*' --numeric-owner
tar xpvf stage3-amd64-musl-openrc-*.tar.xz --xattrs-include='*.*' --numeric-owner
tar xpvf stage3-amd64-musl-systemd-*.tar.xz --xattrs-include='*.*' --numeric-owner

If you want, verify the file's checksum/signature first. If you're downloading something and installing a system on top of it, don't skip this.

Chroot in

Chroot in

Your root filesystem is /mnt/gentoo. First move the DNS setting and virtual filesystems there, then enter it:

cp --dereference /etc/resolv.conf /mnt/gentoo/etc/resolv.conf
mount --types proc /proc /mnt/gentoo/proc
mount --rbind /sys /mnt/gentoo/sys
mount --make-rslave /mnt/gentoo/sys
mount --rbind /dev /mnt/gentoo/dev
mount --make-rslave /mnt/gentoo/dev
chroot /mnt/gentoo /bin/bash
source /etc/profile
export PS1="(gentoo) $PS1"
What is chroot? It's not a virtual machine or a new kernel. It's simply "my root directory is now here", moving you inside Gentoo's filesystem. The kernel is still the live environment's.
Meet Portage

Meet Portage

emerge is the tool you'll use most from Portage. It compiles packages from source; you can also use binary packages if you want.

Install
emerge --ask package
Search
emerge --search package
Update
emerge --ask --update --deep --newuse @world
Preview first
emerge --ask --pretend package
Good habit: Before any big change, use --pretend to see what will be installed/removed. Portage shows you the plan, and you check whether it makes sense.

Binary packages

Gentoo doesn't mean compiling everything for three hours. Using binary packages for huge packages saves serious time.

Pick a profile

Pick a profile

A profile defines the system's overall defaults. A USE flag is a feature choice — for example adding Wayland or Bluetooth support to a package.

eselect profile list
emerge --info | grep '^USE'

Set the right profile based on your choice with eselect profile set <NUMBER>:

KDE + OpenRC
eselect profile set default/linux/amd64/23.0/desktop/plasma
KDE + systemd
eselect profile set default/linux/amd64/23.0/desktop/plasma/systemd
GNOME + OpenRC
eselect profile set default/linux/amd64/23.0/desktop/gnome
GNOME + systemd
eselect profile set default/linux/amd64/23.0/desktop/gnome/systemd
XFCE + OpenRC (no dedicated XFCE profile, general desktop profile)
eselect profile set default/linux/amd64/23.0/desktop
XFCE + systemd (no dedicated XFCE profile, general desktop profile)
eselect profile set default/linux/amd64/23.0/desktop/systemd
LXQt + OpenRC (no dedicated LXQt profile, general desktop profile)
eselect profile set default/linux/amd64/23.0/desktop
LXQt + systemd (no dedicated LXQt profile, general desktop profile)
eselect profile set default/linux/amd64/23.0/desktop/systemd
Server + OpenRC
eselect profile set default/linux/amd64/23.0
Server + systemd
eselect profile set default/linux/amd64/23.0/systemd
No musl profile: musl has no desktop profiles like desktop/plasma (experimental). Use eselect profile list to pick a musl base profile. A desktop environment can still be installed — you just have to set up the USE flags/dependencies yourself (e.g. USE="X wayland qt6 gtk3 pipewire"). That's why the desktop + musl combo is for advanced users.

For systemd, also turn on the global systemd USE flag and turn off elogind (to avoid a conflict):

echo 'USE="${USE} systemd -elogind"' >> /etc/portage/make.conf

Global USE settings go in /etc/portage/make.conf, package-specific ones go in the /etc/portage/package.use/ folder.

mkdir -p /etc/portage/package.use
nano /etc/portage/make.conf
Beginner trap: Don't say "turn everything on". Too many USE flags increase the number of dependencies. Start with the defaults and add as needed.
Skip the kernel

Skip the kernel

Configuring the kernel manually is one of Gentoo's freedoms, but you don't need it for the first install. If you don't want the compiling hassle, use the distribution kernel; sys-kernel/gentoo-kernel-bin, which the Handbook also recommends, provides a ready-made kernel.

For a distribution kernel you also need an initramfs; otherwise GRUB can't find the root filesystem. For this, configure sys-kernel/installkernel with dracut and turn on the dist-kernel USE flag:

echo 'sys-kernel/installkernel dracut' > /etc/portage/package.use/installkernel
echo 'USE="${USE} dist-kernel dracut"' >> /etc/portage/make.conf
emerge --ask sys-kernel/installkernel
emerge --ask sys-kernel/gentoo-kernel-bin

First get the system up and running. Later, if you're curious, you can go into your own kernel config any time; doing it by hand on day one isn't necessary.

Set up the system

Set up the system

Computer's hostname

echo gentoo-lab > /etc/hostname

Time zone

ln -sf /usr/share/zoneinfo/Europe/<REGION>/<CITY> /etc/localtime
echo Europe/<REGION>/<CITY> > /etc/timezone

Locale

Choose the language and locale settings to use. Keyboard layout is a separate setting; don't forget it.

Locale on glibc
nano -w /etc/locale.gen
locale-gen
eselect locale set <NUMBER>
Locale on musl: musl doesn't include glibc's locale-gen command. If you want, install sys-apps/musl-locales for compatibility; set the MUSL_LOCPATH environment variable to /usr/share/i18n/locales/musl, then select with eselect locale list.

Root password

passwd

Start services at boot

In OpenRC you enable services by adding them to a runlevel. If you haven't installed NetworkManager yet, install it, then add it to the default runlevel:

emerge --ask net-misc/networkmanager
rc-update add NetworkManager default

In systemd you enable services with systemctl and make them start at boot. If you haven't installed NetworkManager yet, install it, then start it like this:

emerge --ask net-misc/networkmanager
systemctl enable --now NetworkManager

OpenRC's central settings file is /etc/rc.conf. For the keyboard, /etc/conf.d/keymaps matters; for the clock, /etc/conf.d/hwclock.

In systemd, services are managed with .service units; you start services permanently with systemctl enable --now service.

Install a bootloader

Install a bootloader

Installing GRUB isn't enough; you must make sure the EFI partition is mounted in the right place. For UEFI the Handbook uses the efi-64 platform.

First install the GRUB package (make sure GRUB_PLATFORMS="efi-64" is defined in make.conf):

echo 'GRUB_PLATFORMS="efi-64"' >> /etc/portage/make.conf
emerge --ask sys-boot/grub

Then do the install and generate the menu:

grub-install --target=x86_64-efi --efi-directory=/efi
GRUB_GFXMODE=auto grub-mkconfig -o /boot/grub/grub.cfg

The EFI files are written to the ESP of the target disk you installed to. Make sure the correct partition is mounted.

Once more: Before grub-install, verify the correct ESP is mounted with mount | grep /efi and lsblk.

On MBR + BIOS there is no EFI partition; GRUB writes itself directly to the disk's boot area (the MBR). GRUB_PLATFORMS="pc" is required.

echo 'GRUB_PLATFORMS="pc"' >> /etc/portage/make.conf
emerge --ask sys-boot/grub

Then do the install and generate the menu. For <TARGET_DISK> use the whole disk name, not a partition (e.g. /dev/sda):

grub-install /dev/<TARGET_DISK>
GRUB_GFXMODE=auto grub-mkconfig -o /boot/grub/grub.cfg
Once more: On MBR, the grub-install target must be the disk (like /dev/sda), not a partition (not /dev/sda1).
Set up the desktop

Set up the desktop

For a server install we don't set up a graphical desktop or display manager. Internet and basic services are enough. If the network was set up with NetworkManager, you can add a desktop whenever you want in the future.

If you want a desktop after a server: First install the desktop environment packages in this section, then add a display manager. Make your choice and come back here.

We install KDE Plasma. Wayland is the default session of Plasma 6.

emerge --ask kde-plasma/plasma-meta

We install SDDM for the login screen and a portal package so KDE apps can talk to Wayland:

emerge --ask kde-plasma/xdg-desktop-portal-kde
emerge --ask sddm

We install GNOME.

emerge --ask gnome-base/gnome

If you want a lighter install you can use gnome-base/gnome-light. We install GDM for the login screen:

emerge --ask gnome-base/gdm
OpenRC + NVIDIA + GDM note: With the NVIDIA driver and OpenRC, GDM starting a Wayland session can be problematic. As an alternative you can use SDDM (x11-misc/sddm).

We install XFCE.

emerge --ask xfce-base/xfce4-meta

For the login screen you can prefer LightDM or SDDM:

emerge --ask x11-misc/lightdm
emerge --ask x11-misc/lightdm-gtk-greeter

We install LXQt (light, Qt-based).

emerge --ask lxqt-base/lxqt-meta

By default the display-manager option brings SDDM with LXQt; if you want, you can turn off the sddm USE flag and pick another DM.

Run the display manager at boot. With OpenRC you first need gui-libs/display-manager-init and set DISPLAYMANAGER="sddm" (KDE/LXQt), "gdm" (GNOME) or "lightdm" (XFCE) in /etc/conf.d/display-manager.

Display manager · OpenRC
emerge --ask gui-libs/display-manager-init
nano -w /etc/conf.d/display-manager
rc-update add display-manager default
Display manager · systemd
systemctl enable --now sddm.service
# For GNOME: systemctl enable --now gdm.service
# For XFCE:  systemctl enable --now lightdm.service

For audio use PipeWire + WirePlumber, and if you want Bluetooth you can add BlueZ:

emerge --ask media-video/pipewire media-video/wireplumber
emerge --ask net-wireless/bluez
Note: Package names and profile/USE requirements can change over time. If you get an error on a package name, use emerge --search. Part of learning Gentoo is finding the package name.
Graphics driver

Graphics driver

No graphics driver is installed: A server / headless install doesn't need a graphics driver. You don't need to set VIDEO_CARDS.

For NVIDIA the package is x11-drivers/nvidia-drivers. To work with the distribution kernel, the dist-kernel USE flag is also needed.

# "-*" first resets the default video drivers, then selects nvidia.
echo 'VIDEO_CARDS="-* nvidia"' >> /etc/portage/make.conf
mkdir -p /etc/portage/package.use
printf '%s\n' '*/* nvidia vdpau nvenc wayland' > /etc/portage/package.use/nvidia
printf '%s\n' '*/* dist-kernel' > /etc/portage/package.use/dist-kernel
emerge --ask x11-drivers/nvidia-drivers

kernel-open (the open-source layer) can be used on Turing and later (GTX 1650+) cards and comes as the default in modern drivers; you may need to disable it on older cards:

printf '%s\n' 'x11-drivers/nvidia-drivers -kernel-open' > /etc/portage/package.use/nvidia

For NVIDIA to work properly on a Wayland session, nvidia-drm modeset=1 is recommended (on the kernel command line or in /etc/modules-load.d/nvidia-drm.conf):

printf '%s\n' 'nvidia-drm' 'options nvidia-drm modeset=1' > /etc/modules-load.d/nvidia-drm.conf

After installation, check that the driver is loaded:

nvidia-smi
lsmod | grep nvidia

For AMD, the open-source AMDGPU + RadeonSI drivers are used (via media-libs/mesa).

echo 'VIDEO_CARDS="-* amdgpu radeonsi"' >> /etc/portage/make.conf
emerge --ask --changed-use --deep @world

On older AMD cards (pre-GCN) you may also need to add radeon:

echo 'VIDEO_CARDS="-* amdgpu radeonsi radeon"' >> /etc/portage/make.conf
emerge --ask --changed-use --deep @world
Firmware: AMD cards need the Linux firmware package; if you use a distribution kernel, the firmware comes automatically with sys-kernel/gentoo-kernel-bin.

For Intel the open-source driver is used; the modesetting default DDX driver comes with xorg-server.

echo 'VIDEO_CARDS="-* intel"' >> /etc/portage/make.conf
emerge --ask --changed-use --deep @world
Firmware: Intel graphics cards need DMC/GuC/HuC firmware; with a distribution kernel, sys-kernel/gentoo-kernel-bin includes the needed firmware.
Note: On hybrid graphics systems, PRIME and GPU selection need extra setup. First verify the base driver loads correctly.
